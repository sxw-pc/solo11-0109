# 双轨结算核台

本地合成交易事件与日终账单的双轨封账核对。运行期仅 Python 标准库，无网络、真实支付接口或真实资金。`python -m dualsettle demo` 一条命令生成事件、费率、账单，重建实时轨并输出 JSON/Markdown；`python -m pytest -q` 测试。

事件按交易身份去重，状态授权→确认→撤销/退款；业务时间与到达时间均保留。窗口为含起点不含终点的带时区时间段；金额使用 Decimal，费率逐交易舍入到分。日终更正行必须引用旧行，调整独立于原交易。结论为可封账、证据不足、差异；只有全体可封账时 close 才能归档。报告从结论追到来源哈希、事件、费率与批次行。错误码包括 identity_conflict、bad_state、window_ambiguous、rate_ambiguous、orphan_correction、batch_conflict、not_closable、source_changed。演示预期 M1 实时净额 99.00，日终 99.00，结论可封账。

每次核对冻结本次输入摘要与问题清单。费率、交易、账单、调整、事件币种、汇率版本或结算协议改变后，旧报告以 `effective_status=已失效` 显示，不能再把历史“可封账”当成当前结论；下一次核对会在台账中把旧归档运行置为已失效，同时保留它当时的差异证据与交易级汇率来源快照。

跨币种核对照要求事件、结算商户与汇率输入都带身份：

- 每商户结算币通过合同文件 `currencies` 行设定（`merchant`、`currency`）。事件 `currency` 是交易原币；旧 fixture 完全无币种且未配置结算币时仍按同币种 1:1 处理，保留原有费率与金额兼容。一旦配置了结算币，事件缺少原币即视为证据不足，不再默认 1:1。
- 汇率用 `ingest-fx` 导入本地上报价：`base,quote,start_at,end_at,quote_rate,source`，语义为 1 单位 `base` 兑换 `quote_rate` 单位 `quote`。生效区间为含起点不含终点的半开区间，版本边界只命中一个版本；空洞、重叠、未知币种、非有限或非正报价都使相关交易证据不足，不得按 1:1 放行。反向方向不会由倒数推断，必须显式导入。
- 结算协议 `agreements` 以 `merchant,route,start_at,end_at,version,id` 事先选定两条均合法的路线：`original_lock` 的每笔部分退款沿用确认时锁定汇率，`refund_spot` 的每笔退款按自身业务时刻匹配汇率。`freeze-contract` 可把某商户某窗口的协议冻结为运行使用的身份。
- 部分退款先在**原币**累计并校验不超过确认额，再按合同折算；费率只对已确定的结算币确认额按原有逐交易舍入顺序收取，不对混合原币总和直接乘费率。交易级冻结记录确认汇率身份、每笔退款汇率身份、折算金额、舍入残差与来源摘要，报告中可逐项追溯。
- 合成示例：确认 100 EUR（1 EUR=1.20 USD），退款 50 EUR（退款时 1 EUR=1.10 USD），费率 0。`original_lock` 结算币净额 60 USD，`refund_spot` 为 65 USD；同一 USD 账单 60 只在前一路判金额一致，后一路判差异，不能靠账单总额倒推合同。`python -m dualsettle demo-fx` 演示该场景。
- 跨 cutoff 的迟到退款只进入新的运行，旧归档运行的金额与来源证据不被改写。`pytest` 离线覆盖两路线、多个部分退款、版本边界、空洞/重叠、原币超退、输入变更失效、旧同币种兼容与 SQLite 迁移。

授权和确认金额均需为正且有限，确认不得超过授权；费率必须是有限的 `[0,1)` 比例。非法金额或费率进入本次运行的问题证据，结论为证据不足，不能因为账单金额恰好相等就封账。历史运行的问题清单与新运行隔离，旧报告仍可说明当时为何被拒。

争议保留金通过 `reserve-open` 建立案件，再以 `reserve-release` 按序部分释放。每个案件、释放流水及剩余敞口保存在 SQLite；同一序号同一金额可安全重试，冲突或超额释放会拒绝。保留金影响可分配净额，不改写已封账的原核对证据。

受益人分配通过 `agreements` 导入有生效区间和版本的份额协议，`payout-plan` 按指定商户和已封账运行计算可分配额与各受益人份额，`payout-approve` 绑定核对、保留金和协议摘要批准，`payout-status` 可发现批准后输入变化导致的失效。计划和分配行持久保存；份额不完整或冲突将阻断审批。`demo-decisions` 演示保留金与多受益人分配的联合决策。

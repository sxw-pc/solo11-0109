# 双轨结算核台

本地合成交易事件与日终账单的双轨封账核对。运行期仅 Python 标准库，无网络、真实支付接口或真实资金。`python -m dualsettle demo` 一条命令生成事件、费率、账单，重建实时轨并输出 JSON/Markdown；`python -m pytest -q` 测试。

事件按交易身份去重，状态授权→确认→撤销/退款；业务时间与到达时间均保留。窗口为含起点不含终点的带时区时间段；金额使用 Decimal，费率逐交易舍入到分。日终更正行必须引用旧行，调整独立于原交易。结论为可封账、证据不足、差异；只有全体可封账且审核合同已获所需签署时 close 才能归档。报告从结论追到来源哈希、事件、费率与批次行。错误码包括 identity_conflict、bad_state、window_ambiguous、rate_ambiguous、orphan_correction、batch_conflict、not_closable、source_changed。演示预期 M1 实时净额 99.00，日终 99.00，结论可封账。

每次核对冻结本次输入摘要与问题清单。费率、交易、账单或调整改变后，旧报告以 `effective_status=已失效` 显示，不能再把历史“可封账”当成当前结论；下一次核对会在台账中把旧归档运行置为已失效，同时保留它当时的差异证据。`pytest` 固定从本仓 `src` 导入源码。

金额相等本身不再足以封账。`review-register` 登记离线审核人（虚构 id、角色与本地密钥摘要，不连接真实身份服务）；`review-submit` 记录核对提交人；`review-contract` 冻结书面审核合同并选择一条合规路线；`review-sign` 追加签署意见；`review-status` 输出授权结论与完整责任链；`close` 只有在该合同获得所需签署后才归档。签署绑定 `run_id`、`source_digest`、冻结证据摘要、审核人、角色、意见、时间与本地签名摘要，台账只增不改：相同意见重放幂等，改写意见、重复占两票或对旧摘要签字均被拒绝。

同一审核人不能既提交核对又批准封账，也不能以不同角色替同一合同签两票。常规路线要求核对提交人之外两名不同角色的审核人同意；风险复核路线要求财务与风险审核人同意，且任何仍有效的异议必须先由独立仲裁人裁定。路线在收票前由冻结合同决定，收票后切换会被 `route_locked` 拒绝。异议不是缺票：有效异议会以 `objection_pending`/`objection_upheld`/`objection_unresolved` 阻断 `close` 并保留原因；撤销必须由原提出者签署并留存异议与撤销两条历史，不得删除旧证据；仲裁人须独立于提交人与异议人。常规路线下即使仲裁驳回异议也仍需原异议人撤销才能封账，风险路线下仲裁驳回后即可封账；同一证据、同一签署集因合同路线不同而得到不同授权结论，报告会列出路线、席位与结论。`demo-review` 演示风险路线。

授权和确认金额均需为正且有限，确认不得超过授权；费率必须是有限的 `[0,1)` 比例。非法金额或费率进入本次运行的问题证据，结论为证据不足，不能因为账单金额恰好相等就封账。历史运行的问题清单与新运行隔离，旧报告仍可说明当时为何被拒。

争议保留金通过 `reserve-open` 建立案件，再以 `reserve-release` 按序部分释放。每个案件、释放流水及剩余敞口保存在 SQLite；同一序号同一金额可安全重试，冲突或超额释放会拒绝。保留金影响可分配净额，不改写已封账的原核对证据。

受益人分配通过 `agreements` 导入有生效区间和版本的份额协议，`payout-plan` 按指定商户和已封账运行计算可分配额与各受益人份额，`payout-approve` 绑定核对、保留金和协议摘要批准，`payout-status` 可发现批准后输入变化导致的失效。计划和分配行持久保存；份额不完整或冲突将阻断审批。`demo-decisions` 演示保留金与多受益人分配的联合决策。
